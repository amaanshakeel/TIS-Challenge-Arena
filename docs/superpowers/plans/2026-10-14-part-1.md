# Part 1 Implementation Plan

> Implement inline using superpowers:executing-plans, with tests before authentication and database behavior. No Part 2 work.

**Goal:** Deliver the static website foundation, prepared Supabase schema, and approval-aware authentication.

**Architecture:** Multi-page static HTML with shared ES modules; Supabase Auth handles credentials and PostgreSQL handles authorization. Dashboard shells only.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, pinned Supabase browser client, PostgreSQL/RLS. Node is used only for optional development tests.

**Spec:** `docs/superpowers/specs/2026-10-14-part-1-design.md`

## Constraints and review focus

- Preserve Tech and Innovative Society (TIS), TIS Challenge Arena, and Think. Solve. Rise.
- Exactly two dashboards; no scoring/admin-management UI in Part 1.
- Browser role metadata is untrusted; SQL must deny spoofing and direct writes.
- Confirmation callbacks and asset links must retain repository subpaths.
- Invalid configuration, missing profiles, network failures, and callback errors must fail visibly and safely.
- Duplicate registration and signup privacy behavior must have understandable messages.
- No logo image, fabricated rankings, secrets, deployment claims, or external project mutations.
